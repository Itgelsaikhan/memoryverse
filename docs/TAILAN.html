1. Төслийн товч тойм

MemoryVerse бол хэрэглэгчид дурсамжаа хадгалж, ирээдүйн өөртөө захидал битүүмжилж, дэлхийн хүмүүсийн сэтгэл хөдлөл, аз жаргал он жилүүдэд хэрхэн өөрчлөгдөж байгааг бодит өгөгдлөөр харах боломжтой вэб апп юм.

2. Санааг хэрхэн сонгосон

Анхны санаа нь 4 модультай "MemoryVerse" байсан: Memory Vault, Future Simulator, Humanity Map, Time Analytics. Үүнийг үнэлэхэд дараах сул талууд илэрсэн:

  • 4 модуль хоорондоо холбоогүй, 4 тусдаа апп шиг байсан.
  • "Future Simulator" юуг тооцоолохоо тодорхойгүй байсан.
  • Газрын зураг, шинжилгээ хэсэг олон хэрэглэгчгүй бол хоосон харагдах эрсдэлтэй ("cold start" асуудал).

Шийдэл: бүх модулийг "капсул" гэсэн нэг ойлголтоор нэгтгэсэн. Капсул бүр нь агуулга, огноо, байршил, сэтгэл хөдлөл, сэдэв, нээгдэх огноотой. Хоосон харагдах асуудлыг шийдэхийн тулд хуурамч өгөгдлийн оронд жинхэнэ нээлттэй судалгааны өгөгдөл ашигласан.

Мөн өөр хэд хэдэн санааг (open-source хамаарлын эрсдэлийн радар, судалгааны цоорхой илрүүлэгч, бүтээгдэхүүний shrinkflation мөрдөгч, төрийн худалдан авалтын платформ) судалж харьцуулсан. Ихэнх нь зах зээл дээр аль хэдийн байсан тул хичээлийн хугацаа (4–5 долоо хоног) болон эрсдэлийг харгалзан MemoryVerse-ийг сонгосон. Төрийн худалдан авалтын санааг (TenderLens) ирээдүйн тусдаа төсөлд хадгалсан.

   ▼

   ├─ PostgreSQL ── хүснэгтүүд + Row Level Security

   │     ├─ Функцүүд (RPC): битүүмжлэл, төлбөр, Legacy, импорт
   │     └─ pg_cron: өдөр бүрийн Legacy шалгалт

6. Өгөгдлийн сан

Өгөгдлийн сангийн бүтцийг 6 migration файлаар үе шаттайгаар үүсгэсэн (supabase/migrations/):

ФайлАгуулга
0001_initprofiles, capsules хүснэгт, битүүмжлэлийн дүрэм, файл хадгалах сан
0002_delete_capsuleБитүүмжилсэн капсулыг эзэн нь устгах боломж
0003_humanity_mapmoments хүснэгт, admin эрх, улсын статистик, текст хайлт, нийтэд хуваалцах триггер
0004_time_analyticsindicators, indicator_values хүснэгт, дэлхийн дундаж, өсөлт/бууралт, насны статистик
0005_billing_legacypayments, legacy_contacts, legacy_deliveries хүснэгт, багцын хязгаар, demo checkout
0006_schedule_legacyӨдөр бүрийн Legacy шалгалтын хуваарь

Гол хүснэгтүүд: profiles (хэрэглэгч, багц, эрх), capsules (дурсамж ба ирээдүйн капсул), moments (газрын зургийн мөчүүд), indicators ба indicator_values (судалгааны үзүүлэлт), payments (төлбөр), legacy_contacts ба legacy_deliveries (Legacy).

Хурдны шийдэл: 100,000 мөрийн статистикийг хуудас бүр дээр дахин тооцоолохгүйн тулд materialized view ашиглан урьдчилан тооцоолж хадгалдаг. Ингэснээр газрын зураг, шинжилгээний хуудас хурдан ачаална. Текст хайлтад PostgreSQL-ийн full-text search болон GIN индекс ашигласан.

7. Өгөгдлийн эх сурвалжууд — хаанаас, хэрхэн авсан

7.1 HappyDB — 100,533 аз жаргалтай мөч

  • Юу вэ: Олон оронд амьдардаг хүмүүсээс "сүүлийн 24 цаг эсвэл 3 сард таныг аз жаргалтай болгосон зүйл юу вэ?" гэж асууж цуглуулсан 100,000 гаруй бодит хариулт.
  • Хаанаас: Megagon Labs-ийн GitHub хуудас (github.com/megagonlabs/HappyDB), cleaned_hm.csv болон demographic.csv файлууд.
  • Иш татах: Asai, A., Evensen, S., Golshan, B., Halevy, A., Li, V., Lopatenko, A., Stepanov, D., Suhara, Y., Tan, W.-C., Xu, Y. (2018). HappyDB: A Corpus of 100,000 Crowdsourced Happy Moments. LREC 2018. Зохиогчид ашиглахдаа иш татахыг хүсдэг тул README болон газрын зурагт эх сурвалжийг нь заасан.
  • Хэрхэн боловсруулсан (Python):
    1. Мөч бүрийг зохиогчийн нас, хүйс, улсын мэдээлэлтэй нэгтгэсэн.
    2. Хэт богино мөрийг хасаж, 400 тэмдэгтээс урт текстийг тайрсан.
    3. Сэдэв: HappyDB-ийн өөрийн 7 ангиллыг ашигласан (хайр ба гэр бүл, амжилт, найз нөхөд, агшинг мэдрэх, чөлөөт цаг, байгаль, спорт).
    4. Сэтгэл хөдлөл: ангиллаас гаргаж (жишээ нь "амжилт" → бахархал), түлхүүр үгийн дүрмээр нарийсгасан ("remember", "childhood" → санагалзал, "looking forward" → итгэл найдвар).
    5. 13 MB өгөгдлийг gzip-ээр 3.8 MB болгож шахсан.
  • Хэрхэн оруулсан: Admin panel-аар 1000 мөрөөр хэсэглэн ачаалсан. Алдаа гарвал дахин оролддог. Нийт 55 секунд зарцуулсан.
  • Анхаарах зүйл (шударга байдал): өгөгдлийн ~79% нь АНУ, ~17% нь Энэтхэгээс ирсэн. Тиймээс газрын зураг дээр тоо биш хувь хэмжээгээр харуулж, 30-аас цөөн мөчтэй улсад "түүвэр бага" гэсэн анхааруулга гаргадаг.

8. Аюулгүй байдал

Аюулгүй байдлыг зөвхөн дэлгэц дээр биш, өгөгдлийн сангийн түвшинд хамгаалсан. Ингэснээр хэн нэгэн API-аар шууд хандсан ч дүрмийг тойрч чадахгүй.

  • Row Level Security: хэрэглэгч бүр зөвхөн өөрийн капсулыг харна. Нэвтрээгүй хүн хувийн өгөгдөл огт унших боломжгүй.
  • Битүүмжлэл: битүүмжилсэн капсулын агуулгыг өгөгдлийн сан null болгож буцаана. Засах боломжгүй, харин эзэн нь устгаж болно.
  • Эрх: хэрэглэгч өөрийгөө admin болгох, багцаа үнэгүй ахиулах, төлбөрийн бичлэгийг хуурамчаар үүсгэх боломжгүй. Үнийг клиент биш, өгөгдлийн сан тогтооно.
  • Нийтэд хуваалцах: зөвхөн текст, сэтгэл хөдлөл, сэдэв, улс хуваалцагдана. Нэр, зураг, яг байршил хэзээ ч гарахгүй. Ирээдүйн капсул газрын зураг дээр хэзээ ч харагдахгүй.
  • Файл: хэрэглэгч бүр өөрийн хавтастай. Файлыг хугацаатай (1 цаг) гарын үсэгтэй холбоосоор харуулна.
  • Legacy холбоос: 64 тэмдэгттэй санамсаргүй токен, хугацаатай.
  • Нууц түлхүүр: Supabase-ийн service key-г огт ашиглаагүй. Admin үйлдлүүд ч өгөгдлийн сан дотор эрхээ шалгадаг.

Эдгээр дүрэм бүрийг автомат тестээр шалгадаг (11-р хэсэг).

Бүх урсгал (багц сонгох → checkout → эрх нээгдэх → цуцлах → түүх) бүрэн ажилладаг бөгөөд "Demo — бодит мөнгө хасагдахгүй" гэж тодорхой бичсэн. Код нь цаашид Stripe эсвэл QPay-ээр солих боломжтой бүтэцтэй.

Зах зээл: дижитал өвийн (digital legacy) зах зээл 2026 онд ~25.6 тэрбум ам.доллар, 2030 онд ~47.9 тэрбум болох төлөвтэй (Research and Markets, 2026). FutureMe гэх мэт "ирээдүйн өөртөө захидал" үйлчилгээг сая сая хүн ашигладаг нь хэрэгцээ байгааг баталж байна.

10. Олон хэлний дэмжлэг

  • Header дээрх EN | МН товчоор хэлээ солино. Сонголтыг cookie-д нэг жил хадгална.
  • Анх орж ирсэн хүнд браузерынх нь хэлээр автоматаар тааруулна.
  • Бүх текст, сэтгэл хөдлөл, сэдэв, үзүүлэлтийн нэр, огноо, 177 улсын нэр, алдааны мессеж орчуулагдсан. Admin хуудас дотоод хэрэгсэл тул англиар үлдсэн.
  • HappyDB-ийн мөчүүдийн текст эх хэлээрээ (англи) үлдсэн.

11. Чанарын баталгаа: тест ба CI

45 автомат тест бий, бүгд амжилттай давдаг:

  • Unit тест (19): огноо, тоолуур, CSV задлагч, үнэ, график тэнхлэгийн тооцоо зэрэг функцүүд.
  • Олон хэлний тест (9): Монгол толь бичигт Англи хэлний бүх түлхүүр байгаа эсэх, хоосон орчуулга байхгүй эсэх, Монгол огноо ба улсын нэр браузераас хамааралгүй зөв гарах эсэх.
  • Өгөгдлийн сангийн аюулгүй байдлын тест (17): бүх migration-ийг жинхэнэ PostgreSQL дээр ажиллуулж, өөр өөр хэрэглэгчээр нэвтэрсэн мэт туршина: бусдын капсулыг харах, битүүмжлэл, багцын хязгаар, төлбөр хуурамчаар үүсгэх, admin эрх, Legacy дүрэм.

Тест бодитоор ажиллаж байгааг шалгасан: 50 капсулын хязгаарыг санаатайгаар 5000 болгож эвдэхэд тест унаж, алдааг илрүүлсэн.

CI: GitHub руу push хийх бүрт GitHub Actions автоматаар lint → type-check → 45 тест → production build ажиллуулна.

Гараар шалгасан: сайтын бүх гол урсгалыг бодит сайт дээр компьютер болон утасны дэлгэцийн хэмжээгээр, хоёр хэлээр шалгасан.

13. Мэдэгдэж буй хязгаарлалт

  • Имэйл илгээхгүй: имэйл баталгаажуулалт, нууц үг сэргээх, Legacy-г имэйлээр хүргэх боломжгүй. Баталгаажсан домэйнтэй имэйл үйлчилгээ (SMTP) хэрэгтэй.
  • Төлбөр demo: бодит төлбөр авахын тулд Stripe эсвэл QPay-тэй гэрээ хэрэгтэй.
  • Өгөгдлийн тэнцвэргүй байдал: HappyDB-ийн ихэнх нь АНУ, Энэтхэгээс ирсэн.
  • Хайлт: HappyDB-ийн мөчүүд англи хэлтэй тул хайлт англиар ажиллана.
  • Supabase үнэгүй багц: 7 хоног идэвхгүй байвал project түр зогсдог. Dashboard дээрх Restore товчоор сэргээнэ.
  • Нэг дор олон бүртгэл: Supabase нэг IP хаягаас богино хугацаанд хийх бүртгэлийн тоог хязгаарладаг.

15. Цаашдын төлөвлөгөө ба багшаас асуух асуултууд

Санал болгож буй нэмэлтүүд

  • Өдрийн тэмдэглэл + AI зураг: тухайн өдрийн тэмдэглэлийг AI-аар зураг эсвэл комикс болгох, долоо хоногийнхыг хөдөлгөөнт слайдшоу болгох.
  • Зүүдний тэмдэглэл: зүүдээ бичихэд зургаар харуулж, DreamBank-ийн олон мянган зүүдтэй сэдвээр нь харьцуулах. Ингэвэл "их дата" чиглэлтэй ч уялдана.
  • Имэйл үйлчилгээ холбох (баталгаажуулалт, Legacy хүргэлт).
  • Бодит төлбөрийн систем (QPay / Stripe).

Багшаас асуух асуултууд

  1. Өдрийн тэмдэглэл эсвэл зүүдийг AI-аар зурах функц төслийн чиглэлд нийцэх үү? Хоёулаа уу, аль нэг нь үү?
  2. AI зураг үүсгэх API-ийн зардлыг төсөлд ашиглахад асуудалгүй юу, эсвэл demo горим хангалттай юу?
  3. "Их дата" хэсэг одоогийн хэмжээгээрээ (100k мөч + 3 олон улсын үзүүлэлт) хангалттай юу?
  4. Эцсийн тайлан ямар хэлбэр, бүтэцтэй байх ёстой вэ?
